# S1：稳定性修复设计与验收

基线：`main@a0b414e`。范围来自 2026-10-16 S1 审计及用户提供的候选补丁。

- 正常路径：扫描到期的待支付订单 ID，逐单调用事务服务，锁行后重查状态及期限，原子释放预占、更新状态、追加日志。每轮最多 100 单。
- 异常路径：空期限不自动关单；支付成功回调在锁定订单后拒绝到期订单。扫描失败记录日志并在下一轮重试，单单失败不阻断后续订单。
- 权限：不新增 HTTP API；支付回调保留所有权、金额和幂等检查。
- 兼容：不改表结构和历史 Flyway；保留 RabbitMQ，数据库扫描独立运行；商品缓存改完整参数组合键并设置 Redis TTL；demo 只关闭非核心组件健康探测。
- 拒绝方案：仅依赖 RabbitMQ TTL，因 demo 关闭消息时无法回收预占；扫描直接更新状态，因绕过事务、库存和幂等检查。
- 测试：支付迟到拒绝及终态重放、空期限、扫描故障隔离、真实 MySQL 扫描释放和重复触发、支付与关单并发、事务失败回滚、缓存碰撞回归、Rabbit 拓扑开关；完整 Maven 门禁、前端审计及构建、现有 E2E 和故障检查。

用户已明确授权推送 GitHub 并合入主分支，采用任务分支到 main 的 PR，保留 CI 门禁。原始工作树及未提交文件不变。

本轮不扩大到管理员状态流转或 JWT 部署策略；100 条扫描上限在持续失败积压时有饥饿风险，仍为教学演示规模。
