# ADR 001：模块化单体

状态：已采纳（V2 基线）

日期：2026-09

## 问题

课程作品需要同时讲清订单、库存、支付、消息和权限。拆成多个可独立部署服务会把正确性证明耗在网络分区和分布式事务上，而作品集没有真实流量或多团队发布节奏。

## 约束

- Java 17、Spring Boot 3.5、Vue 3，禁止 Spring Cloud / K8s
- 单店、单仓、虚构数据
- 订单、预占、流水必须同事务

## 方案

一个可运行的 Spring Boot 应用，按包划分 `inventory`、`payment`、`prescription`、`procurement`、`messaging`、`security`。模块之间用应用内事件 + JDBC 事件表，而不是跨进程 RPC。

## 失败方案

一开始上微服务 + 最终一致性 Saga。拒绝原因：无法在作业周期内证明库存不为负；也容易把「拆服务」伪装成生产经验。

## 测试 / 结果

- 应用内服务测试覆盖状态冲突与权限
- CI 在原生 MySQL 上跑库存并发与支付幂等（有 `DB_URL` 时）
- 未宣称可独立扩缩容
